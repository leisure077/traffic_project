# 课时 48：出行方式（中1）——段内平均速度与起讫信息

## 一、为什么要在"段内"重算速度

阶段1的 speed 是全表相邻点速度，混入了驻留点。这里在**一个出行段内部**重新算相邻点速度并取平均，更能代表这次出行的实际速度。

## 二、实现（注意 n 点 → n-1 条边）

```python
for (imsi, seg), g in travel.groupby(["imsi","trip_seg"], sort=False):
    if len(g) < 2:
        n_drop_single += 1
        continue
    g = g.sort_values("time_dt")
    lon = g["lon"].to_numpy()
    lat = g["lat"].to_numpy()

    # 相邻点时间间隔（秒），np.diff 长度 n-1，和距离一一对齐
    secs = np.diff(g["time_dt"].to_numpy()).astype("timedelta64[s]").astype(float)
    # 相邻点球面距离（千米），也是 n-1
    d_km = haversine(lon[:-1], lat[:-1], lon[1:], lat[1:], unit="km")

    with np.errstate(divide="ignore", invalid="ignore"):
        spd = d_km * 3600.0 / secs
    valid = (spd > 0) & (spd < ABNORMAL_SPEED)   # 去掉0间隔与异常高速
    if not valid.any():
        n_drop_speed += 1
        continue
    avg_speed = float(np.mean(spd[valid]))
```

### 一个真实修过的 bug：长度对不齐

早期写法用 `g["time_dt"].diff().dt.total_seconds().to_numpy()`，它长度是 **n**（第一条为 NaN），而距离数组长度是 **n-1**，两者相除报：

```
ValueError: operands could not be broadcast together with shapes (2,) (3,)
```

改用 `np.diff(...)` 直接得到长度 n-1 的时间间隔，与相邻距离严格对齐，问题解决。**写向量化运算先确认形状**。

## 三、起讫点与出行距离

```python
first, last = g.iloc[0], g.iloc[-1]
distance_km = haversine(first["lon"], first["lat"],
                        last["lon"], last["lat"], unit="km")
```

- 起讫直线距离 ≠ 实际路径长度，但可作为出行尺度参考；
- start/end 时间、起讫经纬度都记录到结果，便于后续分析出行 OD（起讫点）。

## 四、速度分档阈值

```python
# 仅速度时的粗判（最终还要结合站点证据）
avg_speed < 12   -> 偏慢：步行/骑行 -> 其他
12 <= avg_speed <= 20 -> 公交典型市区速度
avg_speed > 20   -> 地铁或小汽车
```

对应 config：`MODE_OTHER_SPEED=12`、`MODE_BUS_SPEED=20`。这些是经验阈值，可结合城市数据调整。

## 五、为什么取平均而不是最大速度

单次相邻边可能因基站漂移偏高（虽然已 <200 过滤），用段内有效速度均值更稳健，不会被一次跳变带偏。
