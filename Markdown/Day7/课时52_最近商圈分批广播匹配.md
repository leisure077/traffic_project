# 课时 52：实时热力（中1）——最近商圈分批广播匹配

## 一、要做什么

给每个流点找"最近的商圈"：

- 最近距离 < 1000m：打上该商圈 biz_name（属于这个商圈人流）；
- 否则：标记"未命中"，不纳入商圈计数。

## 二、为什么要分批

若一次算全部：25.6 万点 × 104 商圈 ≈ 2668 万个距离，float64 下约 200MB+，数据再大就会吃紧。分成长度 10000 的小批，每批只算 `10000×104 ≈ 104 万` 个数，内存稳定：

```python
BATCH_SIZE = 10000
n = len(stream)
p_lon = stream["lon"].to_numpy()
p_lat = stream["lat"].to_numpy()
matched = np.full(n, -1, dtype=int)     # 每个点命中的商圈编号，-1=未命中

for s in range(0, n, BATCH_SIZE):
    e = min(s + BATCH_SIZE, n)
    d = haversine(p_lon[s:e, None], p_lat[s:e, None],
                  biz_lon[None, :], biz_lat[None, :], unit="m")  # (批点数,104)
    nn = d.argmin(axis=1)          # 最近商圈编号
    nd = d[np.arange(e - s), nn]   # 最近距离
    hit = nd < HEATMAP_MATCH_THRESHOLD   # <1000m
    matched[s + np.where(hit)[0]] = nn[hit]
```

要点：

1. 距离矩阵只在批内生成，用完即释放；
2. `argmin(axis=1)` 得最近商圈，配套取最近距离；
3. 用一个全局 `matched` 数组按位置写回结果；
4. `np.where(hit)[0]` 是"批内命中点的相对下标"，加上起点 s 还原成全局下标。

## 三、把商圈名贴回流点表

```python
stream = stream[matched >= 0].copy()
stream["biz_name"] = biz.loc[matched[matched >= 0], "biz_name"].to_numpy()
```

只保留命中点，并写入对应商圈名。

## 四、真实结果

```
实时流 256212 行，20181003 当日有效点 256212
商圈数量: 104
命中商圈的流点: 159212 行（阈值1000m），覆盖 4 个商圈
```

注意：只有 **4 个商圈**被命中。原因是流点在空间上高度集中（绝大多数围绕太原街等核心区），其余 100 个商圈 1km 内没有流点。这是真实数据特点，不是 bug——热力图只会显示有数据的商圈。

各商圈 10 分钟窗口人流峰值（课时 54 算出）：太原街商圈 2570、沈阳北站 287、中街商圈 215、棋盘山风景区 10。

## 五、方法权衡

- **最近邻 + 半径**：实现简单、可解释（归属最近且在 1km 内的商圈）；
- 局限：商圈边界不是圆形，1km 阈值是近似；两个商圈相邻时边界点可能误归属；
- 可扩展：用商圈多边形做"点在面内"判断、或用多尺度权重/分层网格（geohash、H3）提速。更大数据还可用 KD-Tree/空间索引替代全量广播。
