# 课时 51：实时热力（上）——实时流数据与商圈数据

## 一、目标：商圈"最近 10 分钟人流量"

想象交通指挥中心：要实时知道每个商圈**最近 10 分钟**来了多少人，用于拥堵预警、调度、引导。输入是**实时流数据**（持续到来的位置点），输出是每个商圈、每一分钟的"过去 10 分钟人流计数"。

> 滑动窗口的生活比喻："最近 10 分钟排队人数"——每分钟刷新一次，窗口像一个长度 10 分钟的滑动框，旧的点滑出、新的点滑入。

## 二、实时流数据（真实 4 列，已含经纬度）

`实时流数据.csv`：约 25.6 万行，utf-8，列顺序：

```
time(YYYYMMDDHHMMSS), imsi, lon, lat
20181003000003, 4600..., 123.4xx, 41.8xx
```

读取与日期过滤：

```python
stream = read_csv(STREAM_DATA_FILE, header=None,
                  names=["time","imsi","lon","lat"],
                  dtype={"time":str,"imsi":str})
stream["lon"] = pd.to_numeric(stream["lon"], errors="coerce")
stream["lat"] = pd.to_numeric(stream["lat"], errors="coerce")
stream = stream.dropna(subset=["lon","lat"])
stream = stream[stream["time"].astype(str).str.startswith(TARGET_DATE)]
stream["time_dt"] = pd.to_datetime(stream["time"], format="%Y%m%d%H%M%S", errors="coerce")
stream = stream.dropna(subset=["time_dt"]).reset_index(drop=True)
```

实跑：256212 行全部属于 20181003。

### 重要修正：实时流不用关联基站

原讲义说实时流只有 3 列、要关联基站补经纬度。**真实文件有 4 列、已自带 lon/lat**，直接使用即可，跳过基站关联——一律以真实数据为准。

## 四、整体流程

```
25.6万流点 �─ 最近商圈匹配(1000m内) ─→ 每个点打上 biz_name（否则未命中）
            └─ 按分钟×商圈 计数 unstack
            └─ 补齐全天1440分钟 reindex
            └─ rolling(10) 10分钟滑动窗口求和
            └─ 转长表 [time, biz_name, count] → heatmap_result.csv
```

## 五、两个关键设计问题

1. **25.6 万 × 104 商圈的距离矩阵很大**（约 2668 万个数）：一次性算占内存，所以要**分批广播**（课时 52）。
2. **计数表是稀疏的**：不是每个商圈每分钟都有人，要 reindex 补 0，滑动窗口才连续（课时 53）。
