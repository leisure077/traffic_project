matched = np.full(n, -1, dtype=int)
for s in range(0, n, BATCH_SIZE): ...
stream = stream[matched >= 0]
stream["biz_name"] = ...

# 4) 分钟×商圈计数 -> 补齐1440分钟 -> 10分钟滚动求和 -> 转长表
stream["minute"] = stream["time_dt"].dt.floor("1min")
panel = stream.groupby(["minute","biz_name"]).size().unstack(fill_value=0)

## 三、性能拆解与优化点（Day8 会系统讲，先有体感）

1. **向量化 Haversine**：一次算一批，不写 Python 双重循环；
2. **分批广播**：把内存从"点数×商圈数"压到"批大小×商圈数"；
3. **pandas 内置 rolling**：底层 C 实现，远快于自己维护队列；
4. 更大规模可上：空间索引（KD-Tree/ball tree）、网格分桶（geohash/H3）、只对"活跃点"匹配、增量计算（实时流每来一批只更新窗口，不必每次重算全量）。

## 四、"实时"到底怎么落地（扩展讨论）

当前是对一整天的离线数据模拟滑动窗口。真正的实时系统：

- 用 Kafka 接收实时流，按分钟微批（micro-batch）或事件驱动；
- 维护每个商圈"最近 10 分钟计数"的滚动窗口状态（可过期）；
- 结果写入数据库/Redis，前端热力图按分钟刷新。

课堂项目用历史数据把核心算法讲透，工程上换成流式框架即可——这是答辩时很好的架构延伸话题。
