# 课时 47：出行方式识别（上）——思路与出行段切分

> 文件：`mode.py`，入口 `mode_analysis()`。

## 一、目标

对每次"出行"判断交通方式，分四类：

- **地铁**、**公交**、**小汽车**、**其他**（步行/骑行/无法判定）。

两类信号：

1. **速度信号**：地铁/小汽车快，公交中等，步行骑行慢；
2. **空间信号**：轨迹是否靠近地铁站、公交站（静态站点数据）。

分析单元是"**出行段**"——连续一串 label=1 的点。

## 二、切出行段：驻留点把出行打断

和驻留段相反：连续 label=1 为同一出行段，遇到 0（或换用户）开新段。

```python
df = read_csv(STAGE3_LABEL_FILE, ...)
df["time_dt"] = parse_time(df["time"])
df = df.sort_values(["imsi","time"]).reset_index(drop=True)

user_change = (df["imsi"] != df["imsi"].shift(1)).astype(int)
break_by_stay = (df["label"] == 0).astype(int)
df["trip_seg"] = (user_change + break_by_stay).groupby(df["imsi"]).cumsum()

travel = df[df["label"] == 1]
```

实跑：699 个出行点共切成 **551 个出行段**——大量段只有 1 个点。

## 三、为什么要过滤"单点出行段"

只有 1 个点：

- 无法计算段内移动速度（至少需要相邻两点）；
- 也无法判断一次完整出行。

所以逐段处理时：

```python
for (imsi, seg), g in travel.groupby(["imsi","trip_seg"], sort=False):
    if len(g) < 2:
        n_drop_single += 1
        continue
```

实跑：551 段中 **454 段是单点被丢弃**，最终有效出行段 **97 个**。这也是信令稀疏性的真实体现：一次出行往往只留下很少的点。

## 四、认识站点静态数据

`出行方式静态数据.csv`（GBK，968 行，列序 lon,lat,mode_type,station_name,line_name）：

- mode_type：公交 900 个、地铁 68 个；
- 示例：`123.417133, 41.868337, 地铁, 三台子(地铁站), 2`。

按类型拆成两组：

```python
st = read_csv_gbk(MODE_STATION_FILE, header=None,
                  names=["lon","lat","mode_type","station_name","line_name"])
subway = st[st["mode_type"].astype(str).str.contains("地铁", na=False)]
bus = st[st["mode_type"].astype(str).str.contains("公交", na=False)]
```

用 contains 而不是等于，是为了兼容"地铁站""公交首末站"等写法。

## 五、判定逻辑预告

对每个 ≥2 点的出行段：

1. 用段内相邻点算平均速度（去掉 0 和 >200 的异常）；
2. 统计段内有多少点分别靠近地铁站、公交站（500m）；
3. 综合裁决（课时 50）：
   - 靠近地铁站点数 ≥2 → 地铁；
   - 否则靠近公交站点数 ≥3 → 公交；
   - 否则平均速度 >20 → 小汽车；
   - 否则 → 其他。
