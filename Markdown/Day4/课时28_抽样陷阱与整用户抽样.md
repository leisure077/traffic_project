# 课时 28：抽样陷阱——为什么必须按"整用户"抽样（重点）

## 一、为什么要抽样

全量目标日 51.8 万点 / 5644 用户。阶段2手写 K-Means 含 O(n²) 的轮廓系数计算，全量较慢。课堂希望 1 分钟内跑完，因此默认取约 2 万点（`SAMPLE_ROWS=20000`，设为 0 即全量）。

## 二、看似自然的做法：随机抽 2 万"行"

```python
df = df.sample(n=20000, random_state=42)
```

**实测结果：规则9过滤后只剩 27 个用户、691 行。** 数据几乎废了。

## 三、为什么随机抽行会失败

看真实分布（目标日 518427 行 / 5644 用户）：

- 5353 个用户当天点数 ≥ 20，但**分布极度不均**；
- 最活跃的 31 个用户就贡献约 2 万行；大量"普通"用户只有 50~90 个点。

随机抽 2 万行相当于对每个人只抽 `2万/51.8万 ≈ 3.86%` 的点：

- 一个原本 80 个点的普通用户，抽完只剩约 3 个点；
- 规则9 要求 ≥20 点，于是普通用户几乎全部被删；
- 只有原本 ≥520 点的"超级活跃用户"能幸存——恰好约 27~31 个。

**本质问题：随机抽行把同一个用户的连续轨迹抽碎了，破坏了"轨迹完整性"。**

## 四、正确做法：按整用户抽样

思想：抽样单位应该是"**用户**"而不是"**行**"。选中一个用户，就保留他当天的**完整轨迹**，直到累计点数达到目标。

```python
user_cnt = df.groupby("imsi").size()
eligible = user_cnt[user_cnt >= MIN_POINTS_PER_USER]   # 当天>=20点的用户
if eligible.sum() > SAMPLE_ROWS:
    shuffled = eligible.sample(frac=1.0, random_state=42)  # 打乱用户顺序
    kept, total = [], 0
    for imsi, cnt in shuffled.items():
        if total + cnt > SAMPLE_ROWS and kept:
            continue                 # 当前用户装不下就跳过，继续找更轻的
        kept.append(imsi)
        total += cnt
        if total >= SAMPLE_ROWS:
            break
    df = df[df["imsi"].isin(kept)]
```

要点：

1. 在当天点数 ≥20 的合格用户里随机打乱（保证代表性，不全是超级用户）；
2. 逐个"整用户"纳入，装得下就收、装不下就跳过；
3. 累计点数达到 2 万即停；
4. 被选中用户的点**一颗不拆**，后续规则 9 不会误删。

## 五、两种抽样对比（实测）

| 方式 | 抽样后 | 规则9 后 | 用户数 |
| --- | --- | --- | --- |
| 随机抽 2 万行 | 20000 行 | 691 行 | **27**（轨迹被抽碎） |
| 按整用户抽样 | 19985 行 / 198 用户 | 17362 行 | **196**（轨迹完整） |

后者既控制了数据量，又保留了近 200 个用户的完整一天轨迹，正是我们要的。

## 六、这是一个通用的数据思维

- 抽样单位要和**分析单元**一致：你分析"人"，就应以"人"为单位抽样；
- 时间序列/轨迹数据不能随便打散抽行，否则时序依赖被破坏；
- 工程实现上，这也是"先在全量上做轻量统计（每用户点数），再决定抽样"的典型模式。
