# 课时 39：阶段3——为什么粗筛+聚类之后还要"规则精判"

## 一、回顾前两阶段

- 阶段1：相邻点速度 >8 捞出 806 个疑似出行点；
- 阶段2：把它们聚成 275 个空间簇（含 152 个单点簇）。

但"瞬时速度快 + 空间聚成一堆"还不等于真正的出行，典型反例：

1. **在大商场/校园里走动**：位置在小范围内持续变化，瞬时速度可能 >8，也能聚成簇，但人没离开这个区域——本质是**驻留**；
2. **基站抖动**：即使做了低频点过滤，仍可能有少量高速度孤立点；
3. 反过来，有些真实出行在某些相邻点间速度并不高（堵车、信号间隔长），需要结合整簇形态判断。

所以需要阶段3：**站在"整簇"的视角，用空间展布 + 时间跨度做最终裁决**。

## 二、阶段3的判据（直觉）

对每一个簇，看它的三个代表位置和持续时间：

- 首点、中点、尾点到"簇中心"的距离是否都很小（< `CLUSTER_DIST_THRESHOLD = 1000m`）；
- 整簇从首到尾的时间跨度是否很短（< `TIME_SPAN_THRESHOLD = 2h`）。

判定：

- **三个代表点都挤在中心 1km 内，且前后不到 2 小时**：这是在一个小区域内活动 → **驻留 0**；
- 否则（点拉得开，或持续很久）：是在空间上真正移动 → **出行 1**；
- **单点簇**：一个孤立高速点，直接算 **出行 1**；
- 根本没进聚类的点（cluster=-1，即大量稳定停留点）：默认 **驻留 0**。

## 三、为什么选"首/中/尾"三个点而不是全部点

- 只看首尾可能漏掉"中途绕远又回来"；
- 全量点逐一判距离计算量大且啰嗦；
- 首、中、尾三个代表足以刻画一个簇是否"收拢在小区域"，实现简单、可解释，也和讲义一致。

中点取 `g.iloc[len(g)//2]`（有序点的中间那条）。

## 四、为什么最终标签要回到"全量点"

目的、方式、可视化都需要在**每一个点**上知道是停留还是移动。阶段2只聚了 806 个出行点，所以阶段3把簇结论 merge 回清洗后的 17362 个点；绝大多数没有簇编号（-1）的点天然是驻留。

## 五、真实结果预告

阶段3跑完：

```
单点簇判出行 152 个；多点簇判出行 92 个；多点簇判驻留 31 个
最终：出行点 699（4.0%），驻留点 16663（96.0%）
```

注意：806 个疑似出行点里有 31 个簇（对应部分点）在精判后被"改判"为驻留——这正是规则精判的价值。
