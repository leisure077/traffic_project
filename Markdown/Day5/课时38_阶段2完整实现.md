## 一、输入输出

- 输入：`stage1_travel_points.csv`（806 个疑似出行点，含 speed）；
- 输出：`stage2_cluster.csv`：在出行点基础上增加 `cluster`（簇编号）、`is_single_cluster`（是否单点簇）。

## 二、逐用户聚类（为什么要按人分开）

聚类只在**同一个用户的点**之间进行——不同用户的点不应聚到一起。所以 `groupby("imsi")` 后逐人调用选 K + K-Means：

```python
np.random.seed(RANDOM_STATE)
out_parts, chosen_ks = [], []
for imsi, g in travel.groupby("imsi"):
    X = g[["lon","lat"]].to_numpy(dtype=float)
    labels, best_k = choose_best_k(X)

    g = g.copy()
    g["cluster"] = labels
    size_map = pd.Series(labels).value_counts()
    g["is_single_cluster"] = g["cluster"].map(
        lambda c: 1 if size_map.get(c, 0) == 1 else 0)
    out_parts.append(g)
    chosen_ks.append(best_k)

result = pd.concat(out_parts, ignore_index=True)
```

要点：

1. 聚类前 `np.random.seed(42)`，结果可复现；
2. `choose_best_k` 内部处理"点太少→单簇"；
3. 用 value_counts 标记**单点簇**：某个簇只有一个点（阶段3直接判出行）；
4. 每个用户的簇编号都从 0 开始，但配合 imsi 使用不会混淆。

## 五、阶段1→2 串联后的含义

- 阶段1 用速度捞出 806 个"可能在移动"的点；
- 阶段2 不再逐点看，而是把每个人这些点按空间聚成若干簇；
- 下一步阶段3要回答：每个簇到底是"一次出行途经的点"还是"在某个小区域活动的点"，并把结论贴回清洗全量 17362 个点。

## 六、性能说明（呼应 Day8）

- 轮廓系数/邓恩指数要在 `n×n` 距离矩阵上算，复杂度约 O(n²)；
- 我们按用户分组，单人点数不大（抽样数据下），且距离矩阵只算一次复用给所有 k，因此很快；
- 若跑全量且某些超级用户点数上千，可用：只对候选 k 抽样估计轮廓、或给单人点数设上限。这是 Day8 性能优化的讨论点之一。
