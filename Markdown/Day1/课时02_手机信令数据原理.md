# 课时 02：手机信令数据是怎么来的

## 一、学习目标

- 理解一条手机信令记录产生的过程；
- 说清 imsi、lac、cell、laci、经纬度这些字段的含义；
- 理解为什么信令数据是"**稀疏且有噪声**"的——这决定了后面所有算法的设计。

## 二、手机为什么会留下"位置记录"

手机要打电话、上网，必须和附近的**基站**通信。一个城市被成千上万个基站的信号覆盖，每个基站管一小片区域（称为一个"小区"，cell）。

手机会在下面这些时刻与基站"握手"，于是产生一条信令：

- 开机 / 关机；
- 打电话、收发短信、上网传输数据；
- 从一个基站小区移动到另一个小区（**越区切换**）；
- 周期性位置更新（即使你不动，隔一段时间也会报一次）。

每条记录至少包含：**时间**、**手机的匿名编号**、**连入的基站编号**。基站的经纬度是已知的，于是就能近似得到"某时刻某手机在某基站附近"。

> 注意：信令定位的是**基站的位置**，不是手机 GPS 精确位置。所以它有天然误差（几十米到几百米），而且同一个基站会覆盖很多人——这是后面要做"聚类、速度阈值"的根本原因。

## 三、认识关键字段（对照本项目真实数据）

| 字段        | 全称/含义                                                      | 例子                                          |
| --------- | ---------------------------------------------------------- | ------------------------------------------- |
| imsi      | 用户匿名标识（International Mobile Subscriber Identity），一个手机号对应一个 | `46001********`                             |
| lac_id    | 位置区编号（Location Area Code），一批基站的分组                          | `16481`                                     |
| cell_id   | 基站小区编号                                                     | `536531`                                    |
| laci      | 组合键 `lac_id-cell_id`，用来唯一定位一个基站小区                          | `16481-536531`                              |
| lon / lat | 基站经纬度（从"基站经纬度数据"表关联得到）                                     | `123.40, 41.80`（沈阳一带）                       |
| time      | 时间                                                         | 原始是毫秒戳 `1538498482636`，清洗后 `20181003004122` |

原始数据一行有 10 列，但我们**只用到前 4 列**：时间戳、imsi、lac_id、cell_id。

## 四、一条记录的"还原"过程（项目第一步的直觉）

原始第一列是 `1538498482636` 这样的 13 位数字，它是：

- **毫秒级 Unix 时间戳**：从 1970-01-01 00:00:00（UTC）起经过的毫秒数；
- 它是 **UTC 时间**，我们在中国（东八区），要 **+8 小时**才是北京时间。

```
1538498482636 毫秒
  → 2018-10-02 16:41:22（UTC）
  → 2018-10-03 00:41:22（北京时间，+8小时）
```

再用 `lac_id-cell_id`（即 `laci`）去"基站经纬度表"里查，补出 lon/lat。一条原始记录就被还原成：

```
时间=20181003004122, 用户=xxx, 位置=(123.xx, 41.xx)
```

这正是 Day4 数据清洗要做的两件大事：**时间戳转换** 和 **基站关联补经纬度**。

## 五、为什么数据"稀疏又有噪声"（非常重要）

信令不是 GPS 每秒打点，它有很多"坑"：

1. **不均匀**：人不动时可能几十分钟甚至更久才一条；移动时切换基站反而更密。
2. **定位漂移**：手机可能在相邻基站间来回跳，看起来像"瞬移"，算出几百 km/h 的假速度。
3. **同一分钟重复**：同一时刻可能有多条相似记录。
4. **用户点数差异巨大**：本项目目标日 51.8 万条记录来自 5644 个用户，最活跃的 31 个用户就贡献了约 2 万条，而大量用户只有几十条。
5. **脏编号**：少量 imsi 里混入了 `#`、`*`、空格等字符。
6. **跨天数据**：抽样里也混着 10 月 1 日、2 日的记录，需要只保留目标日 10 月 3 日。

> 记住这 6 点，后面每条清洗规则、每个阈值（速度上限 200、每人至少 20 点、低频点 < 4 次……）都能对应上一个真实的"坑"。

## 六、真实数据分布（实跑结论，后面会反复引用）

- 原始数据：`原始数据.csv`，约 46.6 MB，**532828 行、10 列、无表头**；
- 去脏 imsi 删除 8 行，去空基站编号删除 9 行；
- 目标日（2018-10-03）记录 **518427 行**，跨天删除 14384 行；
- 目标日共 **5644 个用户**，其中 5353 人当天点数 ≥ 20。
