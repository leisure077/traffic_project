## 三、坑 1：全部 CSV 都没有表头

直接 `pd.read_csv("原始数据.csv")`，pandas 会把**第一行数据当成列名**，后面全错位。

正确做法：显式给列名（`header=None, names=...`），只取需要的列（`usecols`）：

```python
import pandas as pd
df = pd.read_csv("原始数据.csv", header=None, usecols=[0, 1, 2, 3],
                 names=["time", "imsi", "lac_id", "cell_id"], dtype=str)
print(df.head())
```

基站、商圈等同理：

```python
station = pd.read_csv("基站经纬度数据.csv", header=None,
                      names=["lon", "lat", "laci"], dtype=str)
biz = pd.read_csv("商业区数据.csv", header=None,
                  names=["lon", "lat", "biz_name"])
```

## 四、坑 2：两个静态数据是 GBK 编码

用默认 utf-8 读"出行目的/方式静态数据.csv"会报：

```
UnicodeDecodeError: 'utf-8' codec can't decode byte ...
```

因为它们是 Excel 另存的中文 GBK 编码。指定 `encoding='gbk'`：

```python
poi = pd.read_csv("出行目的静态数据.csv", header=None,
                  names=["lon", "lat", "poi_type", "poi_name"], encoding="gbk")
```

`utils.read_csv_gbk()` 已经帮你封装好。

## 五、坑 3：时间戳是 13 位毫秒 UTC

首列不是 `2018-10-03` 这样的日期，而是 `1538498482636`。要点：

1. `pd.to_datetime(x, unit='ms')` 按**毫秒**解析；
2. 解析出来是 **UTC**，要 `+8 小时`才是北京时间。

```python
import pandas as pd
t = pd.to_datetime(1538498482636, unit="ms", utc=True) + pd.Timedelta(hours=8)
bj = t.tz_convert(None).strftime("%Y%m%d%H%M%S")
print(bj)   # 20181003004122
```

而实时流的时间已经是 `20181003000003` 字符串，用 `pd.to_datetime(s, format="%Y%m%d%H%M%S")` 即可。

## 六、一个重要发现：实时流不用关联基站

原始讲义曾说实时流是 3 列、需要关联基站补经纬度。但**真实数据有 4 列，已自带 lon/lat**。所以 `heatmap.py` 直接使用第 3、4 列，跳过基站关联——以真实数据为准。这类"讲义与数据不一致"的情况，本项目一律**以实跑探查结果为准**。
