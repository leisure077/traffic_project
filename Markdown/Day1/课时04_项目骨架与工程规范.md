# 课时 04：项目骨架、config 与 utils 设计

## 一、学习目标

- 理解一个规范的数据项目为什么要"配置与逻辑分离"；
- 看懂 `config.py`（集中管理路径与阈值）和 `utils.py`（通用工具）；
- 学会上下文管理器计时器、日志函数的用法。

## 二、为什么需要 config.py

新手常把路径、阈值写得到处都是：

```python
df = pd.read_csv("E:\\某目录\\原始数据.csv")
if speed > 8:        # 8 是什么？
if dist < 1000:      # 1000 又是什么？
```

问题：换台电脑路径就失效；想把速度阈值从 8 改成 10，要翻遍所有文件。

本项目把**所有路径和阈值集中到 `config.py`**，业务代码里只引用常量名：

```python
from config import SPEED_THRESHOLD, CLEANED_DATA_FILE
if speed > SPEED_THRESHOLD: ...
```

这样做的三个好处：**改一处全局生效、常量名自带解释、方便做实验对比**。

## 三、config.py 里都有什么（分类速览）

| 分类 | 代表常量 | 值 |
| --- | --- | --- |
| 路径 | `RAW_DATA_FILE`、`RESULT_DIR`、`FIG_DIR` | 自动定位数据目录 |
| 清洗 | `TARGET_DATE`、`MIN_POINTS_PER_USER`、`SAMPLE_ROWS` | 20181003 / 20 / 20000 |
| 出行驻留 | `SPEED_THRESHOLD`、`K_MIN/K_MAX`、`CLUSTER_DIST_THRESHOLD`、`TIME_SPAN_THRESHOLD` | 8 / 2~10 / 1000 / 2 |
| 出行目的 | `LIVING_DURATION_THRESHOLD`、购物/旅游时段、`PURPOSE_MATCH_THRESHOLD` | 4h、9-21、9-17、1000m |
| 出行方式 | `MODE_OTHER_SPEED`、`MODE_BUS_SPEED`、`MODE_MATCH_THRESHOLD` | 12 / 20 / 500m |
| 热力 | `HEATMAP_WINDOW_SIZE`、`HEATMAP_MATCH_THRESHOLD` | 10 / 1000 |
| 输出 | `CLEANED_DATA_FILE` … `FIG_3D_TRAJ` | 7 CSV + 6 PNG 的完整路径 |

运行 `python config.py` 可打印全部配置并检查数据文件。

自动定位数据目录的核心思路（`_find_data_dir`）：

```python
# 依次：环境变量 -> 项目data目录 -> 各盘符两层内搜索“相关数据”
for drive in ("E:\\", "D:\\", "F:\\", "G:\\"):
    for name1 in os.listdir(drive):
        cand = os.path.join(drive, name1, "相关数据")
        if os.path.isfile(os.path.join(cand, "原始数据.csv")):
            return cand
```

## 四、utils.py：通用工具箱

`utils.py` 不放业务逻辑，只放"**谁都可能用**"的小工具：

| 工具 | 作用 |
| --- | --- |
| `haversine(...)` | 球面距离（Day2 重点手写） |
| `parse_time / format_time` | `'20181003123000'` ↔ datetime |
| `read_csv / read_csv_gbk` | 读 CSV（后者用 gbk 编码） |
| `save_csv` | 存 CSV，自动建目录，默认 `utf-8-sig`（Excel 打开不乱码） |
| `log / log_step` | 带时间戳的日志、步骤分隔标题 |
| `print_df_stats` | 打印 DataFrame 行数、列名、前 3 行 |
| `Timer` | 上下文管理器，统计一段代码耗时 |

### save_csv 为什么用 utf-8-sig

普通 utf-8 存的中文 CSV，Excel 双击可能乱码；`utf-8-sig` 会在文件头加 BOM，Excel 能正确识别中文。

### Timer 上下文管理器怎么用

```python
with Timer("数据清洗"):
    df = do_something()
# 退出缩进时自动打印：[计时] 数据清洗 耗时 12.94 秒
```

原理是类里实现 `__enter__`（进入记开始时间）和 `__exit__`（离开算差值打印）。

## 五、模块之间如何组织

- 每个模块都有一个**主函数**，如 `clean_data()`、`stage1_analysis()`；
- 文件末尾用 `if __name__ == "__main__":` 支持单独运行；
- `main.py` 统一 `import` 8 个主函数，按顺序调用，并做计时和异常兜底。

## 六、好的代码习惯（本项目全程遵守）

1. 函数小而单一，一个函数只做一件事；
2. 关键步骤先打印"处理前→处理后"行数，方便核对；
3. 路径用 `os.path.join` 拼接，不要手写 `\\`；
4. 阈值全部来自 `config.py`；
5. 结果文件列顺序固定，下游模块才好衔接。
